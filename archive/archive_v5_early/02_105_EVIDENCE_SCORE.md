## 근거 실험과 테스트 범위

- `tests/test_service.py`: 실제 TestClient HTTP 요청, SQLite FK, 역할별 사용자, 동일 키 재전송·충돌·규정 변조 등. 41개.
- `tests/test_{resolver,answer_check,release_impact,v4_controls}.py`: v4 참조 로직의 단위 tests 49개 및 subtests 22개.
- 총 `90 passed, 22 subtests passed` (실행환경 Python 3.13, pytest). 자료: `evidence/pytest_v5_log.txt`.
- `GET /api/fixture-regression`: 가상 20개 중 테넌트별 관련 사건만 시행. **LLM 응답 품질의 정확도가 아니다.**
- `scripts/browser_e2e.py`: 실제 Chromium 내 로컬 접속 시도를 만들었으나 실행환경 URL 관리 정책으로 차단(`ERR_BLOCKED_BY_ADMINISTRATOR`). 따라서 **브라우저 E2E 검증 완료라고 주장하지 않음**.

## 105점 달성을 위한 객관적 차단조건

**100점의 필수 조건:** 실제 보험 도메인 전문가 독립 검토; 검수된 비실제 고객 사례 360건; 블라인드 홀드아웃, 인가·권한·RLS 보안검사; Postgres 스키마·마이그레이션; 비교군 B0/B1/B2/T 공정 실험, 브라우저 E2E; 복구·백업·가용성 실측. 목표 수치는 '결과'가 아니다.

**추가 5점:** G1 보험 업무/AI 실무자 2인 인터뷰, G2 타인 Windows 재설치 재현, G3 권한탈취·감사변조·롤백·장애 대응 훈련, G4 외부 코드 리뷰, G5 3번째 업무팩 도입(공통 코어 변경 없이). 각각 완료 증거가 있어야만 +1.
