# 100점 + 실무 초과달성 5점 — 외부 근거·내부 검증 분리 평가

## 1. 점수는 증거에만 붙는다

- **100점 기본:** 공개된 금융당국·금융사·제품 문서에서 유도한 평가축과 실험 필요성을 연결. 하지만 각 점수 자체는 공인 기관의 채용 가중치나 실제 보험사의 구매 점수가 **아니다**.
- **추가 5점:** 상용/현업 수준을 주장하지 않고 현실적인 사용자 검증·재현·운영 모의훈련 증빙에만 부여.
- 같은 기준으로 v3의 71점을 v4에서 재평가하며 설계 글자 수가 늘었다는 이유만으로 크게 가산하지 않는다.
- 매 항목은 문서/코드/테스트/실사용자 증거를 구분. `미구현`은 최대점을 절대 받지 못함.

|---|---|---:|---:|---:|---|
| R01 | 보험 업무·규정 정확성 | 16 | 13 | 13 | 업무 전문가 독립 검수, 날짜·특약·예외 반례 검증 |

**초과 달성 5점:** 각 +1점, 검증 완료 증거 있을 때만 획득.

1. G1 분야별 실무자 2인 이상 인터뷰와 요구사항/설계 피드백을 서면 정리 (현재 0/1)
2. G2 타인이 새 Windows 환경에서 실행해 동일 결괏값 재현한 공개 로그 (0/1)
3. G3 장애/권한 탈취/감사 변조/롤백 4종 게임데이 시행 및 수정 기록 (0/1)
4. G4 외부 오픈소스 프로젝트와 이슈/문서 PR 또는 설계 피드백 교환 (0/1)
5. G5 공통 코어 무수정으로 제3의 보험 업무팩을 추가하고 테스트 통과 (0/1)

**현재 평가: 76/100 + 0/5 = 76/105. 목표 105/105.** 절대평가가 아닌 내부 추적 기준. 채용 통과 확률로 환산 금지.

## 3. 합격/탈락 게이트

- **Gate 0:** 최신 근거·문서정본·합성데이터 안전 확인.
- **Gate 1:** 시점 엔진 100% 단위·경계 테스트; conflict→INCONCLUSIVE.
- **Gate 2:** 단일 사례 UI/API/DB 실제 연결, source→evaluation→review 회귀 E2E.
- **Gate 3:** baseline/candidate frozen dataset, change impact, 누락 테스트 veto.
- **Gate 4:** RLS/복합 FK + SoD + audit 외부 anchor + 동시 승인 409 검증.
- **Gate 5:** 손보·생보 업무팩 실제 E2E, 코어 조건분기 없는지 확인.
- **Gate 6:** B2 경쟁군, 360건 라벨, 원시 결과·통계·비용 공개.
- **Gate 7:** 비개발자 사용성 테스트, 2분 데모, runbook, 재현 문서.
- **Gate 8:** +5 stretch, 각 증거별 확인자료 봉인.

각 Gate를 통과하기 전 이후 Gate를 '완료'라 표시하지 않는다. 자동 코딩 속도에 맞춰 진도를 나누되 날짜를 성과로 평가하지 않는다.
