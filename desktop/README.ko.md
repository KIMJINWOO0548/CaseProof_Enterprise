# CaseProof Enterprise Windows

CaseProof Desktop은 Windows 네이티브 검토 프로그램입니다. 기존 CaseProof `/v1` 웹과 같은 FastAPI 작업공간에 연결합니다. 계정과 요청, 평가, 결정 이력은 서버에서 관리합니다.

## 시작

1. Windows x64 실행 ZIP을 모두 풀고 `CaseProof.Desktop.exe`를 실행합니다. 자체 포함 빌드에는 데스크톱 런타임이 포함됩니다. 협업 작업공간 서버는 별도로 실행합니다.
2. 연결 주소에는 서버 기본 주소를 입력합니다. 개발용 로컬 서버의 기본 주소는 `http://127.0.0.1:8766`입니다. 원격 서버 주소에는 HTTPS를 사용합니다.
3. 서버에서 발급한 **역할별 접속 토큰**으로 연결합니다. 합성 데모의 접속 토큰은 서버가 생성하는 로컬 `profile.json`에서 확인합니다.

로컬 합성 서버는 저장소 루트에서 기존 가상환경으로 실행할 수 있습니다. 새 프로필은 별도 폴더에 생성되며, 다시 같은 프로필을 사용할 때는 `--profile <기존 profile.json 경로>`를 추가합니다.

```powershell
$env:CASEPROOF_DEMO_MODE = '1'
.\.venv\Scripts\python.exe -m scripts.windows_checks scripts.v1_demo --port 8766
```

## 검토 흐름

1. 요청자가 새 변경을 등록하고 전체 사례를 평가합니다. 기존 평가 사례의 주장 일수를 입력하거나 합성 CSV를 먼저 점검할 수 있습니다.
2. 현업 검토자가 요청을 열고 해당 개정, 평가 실행, 검증 사례를 확인합니다. `확인 필요` 필터와 `다음 확인 필요`로 실패·미확정 사례를 이동할 수 있습니다. 사례의 조항·버전·기준일을 넓은 창에서는 오른쪽 근거 영역에서, 좁은 창에서는 선택 행 아래에서 확인합니다. `현업 검토 기록` 또는 `반려` 확인창에는 현재 개정과 참고 사례의 근거가 표시됩니다.
3. 별도 승인자가 데모 승인을 기록합니다. 현재 검토 권한·평가·출처 상태는 서버에서 확인합니다. 승인된 요청의 근거 영역에는 그때 사용한 개정과 평가 실행, 출처 버전, 승인 봉인, 사유가 표시됩니다.
4. 네트워크가 응답을 보내기 전에 끊기면 같은 Windows 사용자, 같은 서버 주소, 같은 역할로 연결하고 `원래 요청 복구`를 선택합니다. 저장 결과를 서버에서 먼저 확인한 뒤 현재 개정은 별도로 조회합니다.

상단에는 선택 요청·개정·평가 실행의 짧은 참조가 표시됩니다. 넓은 창은 요청 목록, 검증 사례, 근거를 검정 3패널로 배치하고 결정 줄은 화면 아래에 고정합니다. 필터에서 선택한 사례가 사라지면 해당 근거도 닫힙니다. 전체 실행 ID와 SHA-256은 감사 참조를 펼치면 읽고 복사할 수 있습니다.

| 키 | 동작 |
| --- | --- |
| `Ctrl+F` | 요청 목록과 검색에 포커스 |
| `Ctrl+N` | 권한이 있는 요청자의 새 초안 |
| `F5` | 목록과 현재 선택의 새로고침 |
| `F6` / `Shift+F6` | 열린 요청 목록, 검토 표, 근거, 결정 줄 사이 이동 |
| `Esc` | 열린 근거 영역 닫기 |

## 기술과 검증 경계

C#과 .NET 10 WPF의 기본 Windows 창, 목록, 표, 대화상자를 사용합니다. 서버의 기존 평가·변경 전이·독립 승인·승인 봉인 계약을 재사용하며 `/api` 데모와 `/v1` 웹도 그대로 제공합니다. 토큰은 메모리에서 사용합니다. 응답 미확정인 요청의 원래 입력과 키는 계정·서버별로 분리하고 Windows 사용자 DPAPI로 보호합니다. 배포 시 서버 주소·역할·TLS는 운영팀이 구성합니다. 현재 로컬 제품 경로는 합성 정책과 데모 승인입니다.

저장 실행 비교에서는 기준과 대상의 사례별 판정과 달라진 항목을 가운데 표에서 확인합니다. 고정된 실행 ID는 감사 참조에 표시됩니다. 승인 당시 자료는 현행 출처 적격 여부와 별도로 읽습니다.

## 빌드

```powershell
dotnet publish desktop/CaseProof.Desktop/CaseProof.Desktop.csproj -c Release -r win-x64 --self-contained true -o ..\CaseProof-Windows
```

현장 실행 검증은 [Windows QA 스크립트](qa/verify_workbench.ps1)를 사용합니다. 이 테스트는 임시 합성 SQLite 서버와 개인용 클라이언트 상태 폴더를 만들고, 실제 열린 Windows 창을 조작합니다.

감자의 Windows 125% 배율에서 1,440×900 및 1,040×820 창을 확인했습니다. 별도 현업 검토자와 최종 승인자, 사례별 근거, 저장 실행 두 건의 실패→통과 비교를 검증했습니다. 응답을 서버 저장 직후 끊고 프로그램을 다시 열었을 때 같은 원래 키로 저장 결과를 한 번 조회했습니다. [Windows 실행 화면](../docs/images/windows-workbench.png) · [검증 결과](../docs/evidence/windows-workbench-checks.json)
